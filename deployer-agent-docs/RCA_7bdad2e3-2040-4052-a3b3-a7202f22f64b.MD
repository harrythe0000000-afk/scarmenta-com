# RCA — scarmenta.com live-casino launch failures (18 Nov 2026)

## Symptom
On https://scarmenta.com/app/live-casino, tapping any Spribe game shows the toast
"This game could not be opened right now. Please try again later." — the HTTP 424 detail
returned by `POST /api/live/launch` when the outbound InfinityAPI call raises `LaunchError`.

## Root cause — (a) Provider GGR Balance depleted (provider-side, NOT credentials/IP)
InfinityAPI returns **HTTP 200** but with a rejection body:
`Provider GGR Balance is depleted. Please recharge your operator account on the provider portal.`

### Proof (production run 7bdad2e3-2040-4052-a3b3-a7202f22f64b)
Backend logs (logger `bulkapi`, today 18 Nov):
```

```
MongoDB `live_sessions` (latest failed docs) all carry:
`reason: "InfinityAPI: Provider GGR Balance is depleted. Please recharge your operator account on the provider portal."`
across providers **Spribe (Goal 904, Trader 5808), Ezugi (Sic Bo 68), Evolution Live Asia (8049, 8074)** — i.e. operator-wide, not Spribe-specific.

MongoDB `settings` doc `{key:"infinity_ggr_alert"}` is SET (at 2026-11-18T12:14:13Z) with the GGR message — the app's own GGR-alert flag fired.

## Ruling out the other candidates
- **(b) IP not whitelisted / unauthorized IP — NO.** Every outbound `POST https://infinityapipro.com/api/v1/launch.php` returned `HTTP/1.1 200 OK`. An IP/auth block would not return 200 with a GGR body. Additionally, at startup (12:10) the auto-import probes succeeded: `Auto import Spribe: ok=True`, `JILI: ok=True`, `PragmaticPlayLive-EU: ok=True`, `Ezugi: ok=True`, `Evolution Live (Asia): ok=True` — all via launch.php. That proves the production outbound IP is whitelisted and credentials/signature are accepted. (Production runs on deployment-cluster-09, not the preview IP 34.170.12.145; the exact prod egress IP is not enumerable from available tooling, but it is demonstrably whitelisted.)
- **(c) Invalid API key / signature / missing env — NO.** `INFINITY_API_KEY` and `INFINITY_CLIENT_SECRET` are both present and non-empty in the production active run (list_secrets: is_empty=false). Successful 200 auto-imports confirm the signature is valid.
- **(d) Game not found — NO** for the player launches (that would be a different error). Note: two startup *probes* at 12:10 (game_uid=474, 7605) returned `Game provider error`, unrelated to the player-facing GGR failures.
- **(e) Timeout / network — NO.** All calls completed with 200 within normal time.

## Did any launch succeed in production today?
**No.** `live_sessions` distinct status = `["failed"]` only; zero docs with status `launched` (today or ever in this collection). However, the system-level **auto-import probes succeeded (ok=True)** today at 12:10 for Spribe, JILI, PragmaticPlayLive-EU, Ezugi, and Evolution Live (Asia) — so connectivity + credentials work; the depletion surfaced on real player launches ~3 min later (12:13+).

## FRONTEND_URL
`FRONTEND_URL` **is set** in the production env (non-empty) on the active run.

## Fix
Provider-side only: recharge the operator / GGR wallet on the InfinityAPI provider portal
(https://infinityapipro.com). No code change, no secret change, no redeploy needed — launches
will resume once the provider GGR balance is topped up. The code path is confirmed working.
